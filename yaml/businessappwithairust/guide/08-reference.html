Chapter 08

Reference

Everything the language offers, on one page. Two files are the authority: language/yaml/eml.schema.json says which keys a model may carry, and language/appwithai-language.json says what the values in them mean — when this page and either file disagree, the file wins.

The document

KeyEach entry carriesPurpose
eml, name, version, description—The language version ("1.0", required) and the application's name, version and description.
enumsname, valuesA closed vocabulary, reusable by attributes and states.
categoriesname; description, icon, color, seq, default, entitiesDashboard grouping. Only name is required.
entitiesname, attributes; help, icon, parent, label, prefix, audited, softDelete, indexesThe tables. Required, and the only required list.
relationshipsfrom, fromCardinality, to, toCardinality; labelHow entities relate, and which side carries the foreign key.
rulesname, entity, event, nodes, edges; priority, actions, decisionTableA decision bound to an entity and a lifecycle event.
stateMachinesname, entity, states, transitions; initial, finalA lifecycle: the legal moves of a status column.
sagasname, entity, steps; trigger, operationA multi-step process across entities.
hooksentity, event, handler; fieldsBinds a handler to a lifecycle event.
hookFlowsname, entity, nodes, edgesThe hooks of one entity drawn as a process, for the reader and the viewer.
rbacentity, action, rolesRestricts an operation (create, read, update, delete) or a transition's trigger to roles.
triggersentity, source, handlerAn event source: cron:, webhook:, message:.
reportsname, sql; title, entity, chart, x, y, helpA question the application's users ask, as the single read-only query that answers it.

Cardinalities

Each end is one of exactly-one, zero-or-one, zero-or-more, one-or-more. Eight pairs are relationships:

fromCardinality → toCardinalityKindExample
exactly-one → exactly-oneone to oneUser has Profile
exactly-one → zero-or-moreone to manyAccount employs Contact
exactly-one → one-or-moreone to many (at least one)Order contains OrderItem
zero-or-more → exactly-onemany to oneDeal in_stage Stage
one-or-more → exactly-onemany to one (at least one)OrderItem belongs_to Order
zero-or-more → zero-or-moremany to manyStudent enrolls Course
one-or-more → one-or-moremany to many (at least one)Author writes Book
zero-or-one → zero-or-onezero or one, both sidesEmployee assigned Desk

Formula operations: multiply, divide, add, subtract (need source + operand), set (needs value, stored unchanged — the only way to pass text), copy (needs source).

Two syntax rules that bite

fields and decisionTable carry JSON inside a YAML string: wrap the whole value in single quotes so JSON's double quotes survive. And quote any scalar holding : , a leading * or a # — a cron source, a colour, a label like "Start: Lead Captured" — or YAML reads it as something else.

Checker codes worth recognising

CodeMeansDo
EML114FK column does not end in _idRename it, or accept a plain string with no lookup
EML117Entity has no primary keyAdd { name: id, type: string, pk: true } (auto-fixable)
EML262A step is missing a required propertyCheck the table above
EML264A step reads a variable nothing publishedPublish it with as / target, or it is a column of the triggering row
EML265Cross-entity write with no row targetingAdd targetSource or targetField
EML272A decision row leaves an output unsetGive every row every column — the engine discards incomplete rows silently
EML284An action names a workflow that does not existFix the name, or declare the workflow
EML286A trigger: rule saga nothing namesAdd the action, or make it automatic
EML421 / EML424No initial state / a state with no path to a terminalFix the machine — a record will get stuck there

EML502An FK with no matching relationshipDeclare the relationship; lookups depend on it
