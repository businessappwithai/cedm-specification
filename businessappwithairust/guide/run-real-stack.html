Chapter 10

Run the real stack

Chapter 09 compiles a model into a runtime that needs no install and no build step — which is what makes it start in seconds, and also what makes its interface a port of the real one rather than the real one. This chapter runs the actual generated application: a Loco.rs (Rust) backend crate, a TanStack Start front end built on the Astryx design system, and the two test suites that come with them.

There is one generator, and both ways of getting the source run it. The download in chapter 09 is generateApplication — the function the appwithai command line calls — running in your tab over an in-memory filesystem; CI generates every published model both ways and requires the two to write the same files, byte for byte, executables included. The only thing the command line adds is cargo fmt over the backend, when cargo is installed.

This one runs on your machine, not in the tab. The backend is a Rust crate, and building it needs cargo — which no browser sandbox provides. Expect the first build to take a few minutes while the dependency tree compiles; later builds are incremental.

1 · Get the source

Either of these produces the same project, named after what you call it:

  • From this site. Open chapter 09, choose or upload a model, and press Download the deployable app (.zip). Nothing is sent anywhere: the project is written in your tab.
  • From the command line, in a checkout of app-with-ai-rust: 
    bun run generate:tanstack -- -i guide/models/crm.eml.yaml -o crm -n crm

Either way you get backend/ (the crate), frontend/ (the bun workspace), tests/ (the end-to-end suites), model/model.eml.yaml (the model it came from), a docker-compose.yml and a README.md.

2 · Run it with Docker

The compose file runs PostgreSQL, the backend and the front end. It refuses to start without three secrets rather than inventing them, and the backend image's entrypoint is the crate's own command line — so the same image migrates and seeds the database before the first start: 

cd crm
export DB_PASSWORD=change-me ADMIN_PASSWORD=change-me JWT_SECRET=$(openssl rand -hex 32)
docker compose build
docker compose run --rm backend db migrate    # the schema
docker compose run --rm backend db seed       # the dictionary, workflows, access rules, accounts
docker compose up

The API answers on http://localhost:3000 — it describes itself at /openapi.json, with browsable references at /redoc and /scalar — and the application is on http://localhost:3001. Sign in as admin@admin.com with the ADMIN_PASSWORD you chose, or as one of the accounts the seed creates for every role the model's rbac declares.

3 · Or run it with cargo and bun

You need a Rust toolchain with cargo, Bun 1.1 or later, and PostgreSQL 14 or later. The database is named after the crate, with _development on the end: 

createdb crm_development
cd crm
bun install                      # the front end's dependencies
cp backend/.env.example backend/.env
bun run db:migrate               # cargo loco db migrate
bun run db:seed                  # the dictionary, workflows, access rules, accounts
bun run dev                      # the API on :3000 and the front end on :3001

cargo loco is not something to install: the backend ships a .cargo/config.toml aliasing it to the crate's own command-line binary, which provides start, db migrate, db seed, task and the rest.

4 · Prove it

The application carries two independent suites over the same HTTP surface, both generated from the model, so both grow when the model does: 

createdb crm_test
cd crm/backend
LOCO_ENV=test cargo test --test app           # the request suites — the primary gate
cargo clippy --all-targets -- -D warnings     # expected clean

cd ../tests
bun run test                                  # the bun:test suites; starts the backend itself

How this differs from chapter 09

Both chapters compile the same model with the same compiler. What they do afterwards is the whole difference, and it is a real trade rather than one being a lesser version of the other.

Chapter 09 — the browser runtime

  • Starts in seconds
  • No install, no build, and nothing fetched from another host
  • PostgreSQL in the tab, application server on a worker
  • Its interface is a port of the generated one
  • Nothing to open and edit per entity

This chapter — the real stack

  • Minutes for the first build, most of it compiling Rust
  • Runs on your machine: cargo, bun and PostgreSQL, or Docker
  • The real Loco.rs API, enforcing access, workflows and rules
  • The actual generated React front end
  • Five hundred files you can read, change and deploy
